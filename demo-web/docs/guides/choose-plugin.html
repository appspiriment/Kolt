Choose a Convention Plugin

Kolt bundles its Gradle rules into 12 convention plugins. Use this guide to determine which plugin to apply to your module.

Decision Flowchart

Follow the tree below to identify the plugin that best matches your target platforms and dependency needs:

Target Module Type?
 ├── Application ──► Android-only? ──► Use: android-application
 │                 └── KMP? ─────────► Use: kmp-application
 └── Library ──────► Android-only? ──► Needs Hilt? ──► Needs Compose? ──► Use: android-library-hilt-compose
                   │                                  └── No Compose? ─► Use: android-library-hilt
                   │                 └── No Hilt? ───► Needs Compose? ──► Use: android-library-compose
                   │                                  └── No Compose? ─► Use: android-library
                   └── KMP? ─────────► Needs Koin? ──► Needs Compose? ──► Use: kmp-library-koin-compose
                                                      └── No Compose? ─► Use: kmp-library-koin
                                     └── No Koin? ───► Needs Compose? ──► Use: kmp-library-compose
                                                      └── No Compose? ─► Use: kmp-library

Specialized Data Layers

If your module is dedicated strictly to repositories, databases, or networking clients, apply the specialized data layer plugins. These bundle Room/SQLDelight schemas and Retrofit/Ktor networking setups:

  • Android-only data: Apply android-data-layer.
  • KMP shared data: Apply kmp-data.
